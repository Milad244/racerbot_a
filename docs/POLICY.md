# Team A Policies

## Research Documentation

Research needs to be filled with new information and discoveries, especially with regard to learnings from the nodes. For example: "We tried this and it didn't work because of X," or "This worked," or "We ran into this problem, and we can mitigate it by doing that." This way, we don't repeat our mistakes and can build a map of what we've tried and what works.

**Policy:** Every new feature or major change must have a corresponding edit to `RESEARCH.md`.

## Lecture Comprehension

Having a good understanding of each Roboracer lecture is critical to being able to code our nodes. There is a Kahoot for each lecture to ensure this, and you must **use your real name when joining**. If you attend the Kahoot meeting, questions are presented in chronological order. If you miss the meeting or score below 70%, you are **required** to retake the Kahoot via a Kahoot assignment (questions in random order) found [here](LINK TODO), retrying with your name plus "2", "3", etc. (e.g., "Jane2") until you score 70% or above.

**Policy:** You must attend each lecture's Kahoot and score at least 70%, or redo it via the assignment linked above.

## Active Contribution

Meaningful work must be done to stay on the team. You will be assigned specific or high-level tasks via GitHub Issues in our [GitHub Project board](https://github.com/orgs/sfu-racerbot/projects/3), with a deadline agreed upon in advance. If your task requires collaboration, take the initiative to start a Discord thread for it.

**Policy:** Each task requires both a genuine PR and clear, active communication before the deadline. If you don't meet this bar for more than 2 tasks in a term, you will be removed from the team, though you're welcome to rejoin once you can commit the necessary time.
